# Testly — платформа для A/B экспериментов

**Testly** — инструмент для проведения A/B-экспериментов на веб-страницах. Позволяет сравнивать два варианта страницы, собирать поведенческие данные пользователей и получать статистически обоснованные выводы о том, какой вариант работает лучше.

## Как это работает

**1. Создание эксперимента**

Через дашборд загружаются два HTML-варианта страницы (A и B). Система генерирует публичную ссылку, по которой пользователи попадают на один из вариантов — группа определяется автоматически и фиксируется в cookie.

**2. Сбор данных**

На тестируемых страницах работает клиентский трекер. Он автоматически фиксирует клики, глубину прокрутки, взаимодействие с формами, ошибки и время сессии. Каждый пользователь получает анонимный идентификатор — персональные данные не собираются.

**3. Статистический анализ**

После завершения эксперимента Python-модуль рассчитывает UX-метрики по обеим группам:

| Метрика | Описание |
|---|---|
| `form_completion_rate` | Конверсия в отправку формы |
| `avg_session_duration` | Среднее время на странице |
| `avg_scroll_depth` | Глубина прокрутки |
| `bounce_rate` | Доля отказов |
| `confusion_index` | Хаотичные клики (индикатор запутанности интерфейса) |
| `error_rate` | Частота ошибок |

Для бинарных метрик применяется z-тест для двух пропорций, для количественных — критерий Уэлча. Дополнительно рассчитываются доверительные интервалы (95%) и мощность теста.

**4. Дашборд**

Результаты отображаются в браузере: таблица сравнения A vs B, p-value, статус значимости и графики.

## Быстрый старт

### 1. Клонирование и зависимости

```bash
git clone <URL-репозитория>
cd ux_reserch
npm install
```

### 2. База данных

Создайте пустую базу (имя по умолчанию в коде — `ux_ab_testing`, можно другое через переменные окружения).

Примените схему из репозитория:

```bash
psql "postgresql://USER:PASSWORD@HOST:PORT/DBNAME" -f db/schema.sql
```

### 3. Переменные окружения

Сервер читает параметры БД из переменных окружения. Создайте файл .env в корне проекта:

| Переменная     | По умолчанию   | Описание        |
|----------------|----------------|-----------------|
| `DB_HOST`      | `localhost`    | Хост PostgreSQL |
| `DB_PORT`      | `5432`         | Порт            |
| `DB_NAME`      | `ux_ab_testing`| Имя базы        |
| `DB_USER`      | `postgres`     | Пользователь    |
| `DB_PASSWORD`  | `postgres`     | Пароль          |


### 4. Запуск

```bash
npm start
```

Сервер слушает порт **3000** (задано в `server.js`).

### Основные URL

| URL | Назначение |
|-----|------------|
| `http://localhost:3000/` | Лендинг |
| `http://localhost:3000/dashboard` | Дашборд: регистрация, проекты, эксперименты |
| `http://localhost:3000/exp/<id>` | Публичная страница эксперимента (вариант A или B по cookie `ab_group`; для предпросмотра: `?preview=A` или `?preview=B`) |

Статика отдаётся из каталога `public/` (в т.ч. `public/tracker.js` для страниц экспериментов).

### Эксперименты

- Создание через дашборд: загрузка двух файлов с **точными именами** `variant_A.html` и `variant_B.html` (лимит размера одного файла в `server.js`, по умолчанию 2 МБ).
- Файлы сохраняются в `storage/experiments/<experiment_id>/`.
- Публичная ссылка на тест хранится в БД и имеет вид `https://<ваш-хост>/exp/<id>`.

### Трекинг

- Приём событий: `POST /api/track` (JSON-массив событий).
- Дополнительно события дописываются в файл `data/events.log` (каталог `data/` создаётся при старте, если его нет).

### Статистический анализ (Python)

Для автоматического расчёта статистики при завершении эксперимента требуется Python 3 и установка зависимостей:

```bash
pip install psycopg2-binary statsmodels scipy python-dotenv
```
Если Python или пакеты недоступны, основное приложение продолжает работать — статистику можно рассчитать вручную.
