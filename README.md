# Testly — платформа для A/B экспериментов

Веб-приложение на **Node.js (Express)** с **PostgreSQL**: лендинг, личный кабинет с проектами, создание экспериментов с загрузкой HTML-вариантов, страницы тестов, сбор событий трекера и дашборд метрик.

## Требования

- **Node.js** 18+ (рекомендуется LTS)
- **PostgreSQL** 14+ (или совместимая версия, под которую собран дамп в `db/schema.sql`)
- **Python 3** — только если нужен автоматический статистический анализ при завершении эксперимента (см. раздел ниже)

## Быстрый старт

### 1. Клонирование и зависимости

```bash
git clone <URL-репозитория>
cd ux_reserch
npm install
```

### 2. База данных

Создайте пустую базу (имя по умолчанию в коде — `ux_ab_testing`, можно другое через переменные окружения).

Примените схему из репозитория:

```bash
psql "postgresql://USER:PASSWORD@HOST:PORT/DBNAME" -f db/schema.sql
```

Если дамп был сделан без флагов `pg_dump`, в файле могут быть строки вроде `CREATE SCHEMA public` или `OWNER TO postgres`. На «чистой» базе иногда удобнее пересобрать дамп так:

```bash
pg_dump --schema-only --no-owner --no-privileges -f db/schema.sql ...
```

### 3. Переменные окружения

Сервер читает параметры БД из переменных (см. `src/services/database.service.js`):

| Переменная     | По умолчанию   | Описание        |
|----------------|----------------|-----------------|
| `DB_HOST`      | `localhost`    | Хост PostgreSQL |
| `DB_PORT`      | `5432`         | Порт            |
| `DB_NAME`      | `ux_ab_testing`| Имя базы        |
| `DB_USER`      | `postgres`     | Пользователь    |
| `DB_PASSWORD`  | `postgres`     | Пароль          |

Создайте файл `.env` в корне проекта (он в `.gitignore`) или экспортируйте переменные в shell перед запуском.

### 4. Запуск

```bash
npm start
```

Сервер слушает порт **3000** (задано в `server.js`).

## Основные URL

| URL | Назначение |
|-----|------------|
| `http://localhost:3000/` | Лендинг |
| `http://localhost:3000/dashboard` | Дашборд: регистрация, проекты, эксперименты |
| `http://localhost:3000/exp/<id>` | Публичная страница эксперимента (вариант A или B по cookie `ab_group`; для предпросмотра: `?preview=A` или `?preview=B`) |

Статика отдаётся из каталога `public/` (в т.ч. `public/tracker.js` для страниц экспериментов).

## Эксперименты

- Создание через дашборд: загрузка двух файлов с **точными именами** `variant_A.html` и `variant_B.html` (лимит размера одного файла в `server.js`, по умолчанию 2 МБ).
- Файлы сохраняются в `storage/experiments/<experiment_id>/`.
- Публичная ссылка на тест хранится в БД и имеет вид `https://<ваш-хост>/exp/<id>`.

## Трекинг

- Приём событий: `POST /api/track` (JSON-массив событий).
- Дополнительно события дописываются в файл `data/events.log` (каталог `data/` создаётся при старте, если его нет).

## Статистический анализ (Python)

При **завершении** эксперимента бэкенд может запускать `statistical_analyzer.py` через `stats.service.js`.

Нужны:

- интерпретатор Python (`python3` по умолчанию, переопределение: переменная **`PYTHON_BIN`**);
- зависимости, которые импортирует скрипт (установите в своё окружение), например:

```bash
pip install psycopg2-binary statsmodels scipy python-dotenv
```

Скрипт читает те же переменные `DB_*`, что и Node (через `python-dotenv` и `.env`).

Если Python или пакеты недоступны, основное приложение всё равно может работать; может пострадать только шаг автоматического пересчёта статистики при `complete`.

## Структура репозитория (кратко)

| Путь | Назначение |
|------|------------|
| `server.js` | Точка входа Express, маршруты |
| `public/landing/` | Лендинг |
| `public/dashboard/` | Дашборд |
| `public/tracker.js` | Клиентский трекер |
| `src/controllers/` | HTTP-контроллеры |
| `src/services/` | БД, метрики, трекинг, статистика |
| `db/schema.sql` | SQL-схема для инициализации БД |
| `storage/experiments/` | Загруженные варианты html-страниц |
